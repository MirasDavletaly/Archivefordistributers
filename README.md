# Архив поставщиков

Веб-приложение для архива дистрибьюторов, брендов и контактов. Главный экран — поиск:
одно поле, которое ищет одновременно по названиям поставщиков, брендам, именам контактов,
почтам и телефонам, терпит опечатки и показывает, почему запись найдена.

Данные загружены из `Authorized Dealers & Distributors.xlsx`: **72 поставщика**
(38 дистрибьюторов и 34 прямых), **225 брендов**, 287 связей и 114 контактов.

## Запуск

Нужен Node.js 23 или новее (рекомендуется 24 LTS). Внешних зависимостей нет — `npm install` не требуется.

```bash
node server.mjs
```

Откройте http://localhost:3000. При первом запуске база создаётся автоматически
из `data/seed.json`.

С паролем на входе:

```bash
# Linux / macOS
ARCHIVE_PASSWORD="ваш-пароль" ARCHIVE_SECRET="длинная-случайная-строка" node server.mjs

# Windows PowerShell
$env:ARCHIVE_PASSWORD="ваш-пароль"; $env:ARCHIVE_SECRET="длинная-случайная-строка"; node server.mjs
```

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ARCHIVE_PASSWORD` | Общий пароль на входе. Если пустой — архив открыт всем, у кого есть ссылка | не задан |
| `ARCHIVE_SECRET` | Ключ подписи сессий. Без него при перезапуске все входы сбрасываются | случайный |
| `PORT` | Порт | `3000` |
| `ARCHIVE_DB` | Путь к файлу базы | `data/archive.db` |

## Что умеет

**Поиск.** Ищет по всем полям сразу. Несколько слов работают как «И» — все должны совпасть.
Терпит опечатки: `shneider` находит `SCHNEIDER ELECTRIC`, `ibemmo` находит `IBEMO`.
Телефон ищется по любому фрагменту независимо от формата записи. Под каждой карточкой
написано, по какому полю нашлось совпадение. Клавиша `/` ставит курсор в поиск.

Опечаткоустойчивость иногда даёт лишний результат в конце списка — например, запрос `hawk`
кроме бренда `HAWKE` покажет и `HACK`, который отличается одной буквой. Это цена того,
что опечатки прощаются; такие совпадения всегда стоят ниже точных.

Поиск **не переводит между языками**: `Шнайдер` не найдёт `SCHNEIDER`, а `насосы` не найдёт
`насос`. Это осознанное ограничение — если понадобится, добавляется отдельно.

**Редактирование.** Кнопка «Изменить» есть и в карточке поиска, и на странице поставщика.
Правятся все поля, бренды привязываются и отвязываются по одному, контакты добавляются,
меняются и удаляются. Кнопка «+ Добавить поставщика» в шапке создаёт новую запись.

**Бренды — отдельные страницы.** Открыв бренд, видно всех, кто его возит. Это отвечает на
вопрос «у кого взять X». При вводе бренда подсказываются уже существующие, чтобы не плодить
дубли; `hawke` и `HAWKE` считаются одним брендом. Переименование в уже существующий бренд
объединяет записи.

**Язык интерфейса.** Основной — английский. Кнопка в шапке (и на экране входа) переключает
на русский и обратно; выбор запоминается в браузере у каждого человека отдельно. Переключаются
все подписи, включая вид поставщика и статус — в базе они хранятся кодами (`distributor`/`direct`,
`active`/`reserve`/`blacklist`), а подпись подставляет интерфейс. Искать статус можно словом на
любом из двух языков: и `reserve`, и `резерв` находят одно и то же.

**Экспорт CSV** — кнопка в шапке, файл открывается в Excel без проблем с кириллицей.
Выгрузка приходит на языке интерфейса (`/api/export.csv?lang=ru` — принудительно по-русски).

## Публикация в интернете

Приложение хранит данные в файле SQLite, поэтому хостинг должен давать **постоянный диск** —
иначе правки будут исчезать при каждом перезапуске. В проекте есть `Dockerfile`, который
кладёт базу в том `/data`.

Подходящие варианты:

- **Fly.io** — `fly launch`, затем `fly volumes create data --size 1` и монтирование в `/data`.
  Бесплатного лимита для такого приложения хватает.
- **Railway** — подключить репозиторий, добавить volume на `/data`.
- **Render** — Web Service + Persistent Disk (диск платный, от нескольких долларов в месяц;
  на бесплатном тарифе диска нет и данные будут сбрасываться).
- **Свой сервер или VPS** — `docker build -t archive . && docker run -d -p 80:3000 -v archive:/data -e ARCHIVE_PASSWORD=... archive`

Перед публикацией обязательно задайте `ARCHIVE_PASSWORD` и `ARCHIVE_SECRET`.

**Про пароль честно:** один общий пароль защищает от случайных посетителей, но не разделяет
права — любой, кто вошёл, может менять и удалять записи, и не видно, кто что изменил.
Для личных логинов, ролей «только чтение» и истории правок нужна отдельная доработка.

## Обслуживание

```bash
# Повторный импорт из Excel в data/seed.json
node scripts/import-xlsx.mjs "путь/к/файлу.xlsx"

# Пересоздать базу из seed.json (ВНИМАНИЕ: правки из интерфейса будут потеряны)
node scripts/reset-db.mjs --force

# Тесты
node --test "test/*.test.mjs"
```

**Резервная копия** — это просто копия файла `data/archive.db`. Копируйте его при
остановленном сервере, либо выгружайте CSV из интерфейса.

```

public/app.js           Экраны: поиск, поставщик, бренд, список брендов

public/i18n.js          Переводы интерфейса (английский и русский)
public/styles.css       Оформление
scripts/import-xlsx.mjs Excel -> data/seed.json
scripts/xlsx-reader.mjs Чтение .xlsx без внешних библиотек

data/archive.db         Рабочая база (не в git, создаётся при запуске)
```

## Модель данных

- **suppliers** — поставщик: название, вид (`distributor` или `direct`), город, страна,
  сайт, телефон, почта, условия, статус (`active`, `reserve` или `blacklist`), заметки
- **brands** — бренд, уникальный по названию без учёта регистра
- **supplier_brands** — связь многие-ко-многим: кто какой бренд возит, с примечанием
- **contacts** — люди у поставщика: имя, должность, почта, телефон, примечание

Поля «город», «страна», «сайт», «условия» в исходном Excel отсутствовали — они пустые
и заполняются через интерфейс.

## API

Все пути требуют входа, если задан `ARCHIVE_PASSWORD`.

```
GET    /api/search?q=&kind=&limit=    поиск по поставщикам и брендам
GET    /api/stats                     счётчики
GET    /api/suppliers                 список
POST   /api/suppliers                 создать
GET    /api/suppliers/:id             карточка с брендами и контактами
PATCH  /api/suppliers/:id             изменить
DELETE /api/suppliers/:id             удалить
POST   /api/suppliers/:id/brands      привязать бренд { name }
DELETE /api/suppliers/:id/brands/:brandId
POST   /api/suppliers/:id/contacts    добавить контакт
PATCH  /api/contacts/:id              изменить контакт
DELETE /api/contacts/:id              удалить контакт
GET    /api/brands                    все бренды с числом поставщиков
GET    /api/brands/:id                бренд и кто его возит
PATCH  /api/brands/:id                переименовать { name }
GET    /api/export.csv?lang=en|ru     выгрузка в CSV
```

Ошибки возвращают поле `code` (`name_required`, `not_found`, `brand_name_required`,
`wrong_password`, `unauthorized`) — интерфейс по нему подбирает сообщение на своём языке.
